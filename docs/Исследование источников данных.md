# Обзор источников данных о новых судебных делах

> Итоги исследования способов получения судебных дел для системы автоматизированного
> информирования потенциальных клиентов (тестовое задание «PolDoma»).
> Дата составления: 24.09.2026.

## 1. Постановка

Требуется автоматически получать **новые судебные дела** (в идеале — по роли
«ответчик»), сопоставлять их с нашей базой контактов, рассылать КП, фиксировать
отправки и передавать ответы клиентов в Bitrix24.

## 2. Рассмотренные варианты

### 2.1. КАД kad.arbitr.ru («Картотека арбитражных дел») — парсинг напрямую

**Статус: основной способ.**

- Официального публичного API у КАД **нет**, но сайт сам использует внутренний
  JSON-эндпоинт `POST https://kad.arbitr.ru/Kad/SearchInstances`
  (аналогичные: `SearchAdmin` — административные, `SearchBankruptcy` — банкротные
  дела). Тело запроса — JSON с фильтрами (суды, тип дела, даты регистрации,
  участник и его роль, страница). Ответ — список дел: номер, суд, судья,
  истец/ответчик с ИНН, дата регистрации, GUID карточки (`/Card/{guid}`).
- Заголовки: `Content-Type: application/json`, `x-date-format: ignore-timezone`,
  cookie сессии.
- **Главная сложность — Cloudflare** (JS-челлендж + капча). Обычный `requests`
  получает 403. Проверенное сообществом решение: отдельный
  **cookie-fetcher на Playwright** (headless-браузер проходит челлендж, cookies
  сохраняются и переиспользуются в лёгких HTTP-запросах; при 403 — обновление).
- Рабочие открытые проекты-примеры (GitHub, обновлялись 2021–2025):
  - `zeotq/court-case-monitor` — FastAPI + микросервис cookie-fetcher на Playwright;
  - `BondarenkoVyacheslav/kad.arbitr.ru-parser`, `yuglebov/kad_arbitr_ru`,
    `RB-PRO/KadTG` (Go) и др.
- Условия использования сайта ограничивают автоматизированный доступ — для
  тестового задания приемлемо, для продакшена нужно учитывать риски блокировки.

### 2.2. Платный агрегатор parser-api.com — не используется в данном проекте

Рассмотрен в ходе исследования, но **в проекте не применяется**: API-ключ
получить на текущий момент не удалось, и использование агрегатора не
предполагается. Ниже — зафиксированные результаты изучения (историческая
справка для полноты анализа):

- Единый стабильный API над КАД: `GET /search` (поиск по датам, ИНН/наименованию,
  роли участника `Respondent`, типу дела A/G/B, суду), `details_by_number`,
  `details_by_id`, `pdf_download`.
- Тариф: **200 запросов в месяц бесплатно**; лимит расходуют только успешные
  (`Success=1`) запросы, ошибки источника бесплатны и подлежат повтору.
- Документация отличная: текстовая + OpenAPI (файл `kad-arbitr-openapi.yaml`
  лежит в корне проекта) + интерактивная Swagger-версия.
- Важные выводы из документации: параметр `Inn` принимает ИНН **или
  наименование** (пример с «РОСНЕФТЬ»); поиск по датам без участника — под вопросом,
  требует проверки тестовым запросом.
- **Причина отказа:** API-ключ на текущий момент получить не удалось;
  использование агрегатора в данном проекте не предполагается.

### 2.3. API-Cloud.ru — платный агрегатор

- Каталог из ~30 источников: kad.arbitr, ras.arbitr, ГАС «Правосудие», суды
  Москвы, ФССП, ФНС, Федресурс и др.
- Оплата поштучно **от 0,20 ₽/запрос** (без бесплатного месячного лимита),
  ДЕМО-доступ предоставляют по запросу в чат/на support@api-cloud.ru.
- Минусы: документация закрыта за личным кабинетом, регистрация только для юрлиц.
- **Статус: не используется** (документация закрыта за личным кабинетом,
  регистрация только для юрлиц).

### 2.4. ГАС «Правосудие» (sudrf.ru) — не подходит

- Система для судов **общей юрисдикции и мировых судей**, а не арбитража —
  другое ядро аудитории (споры физлиц: алименты, ДТП, потребительские споры),
  слабо совместимой с B2B-рассылкой КП.
- **API не существует вообще** (ни официального, ни стабильного внутреннего).
  Данные разбросаны по тысячам отдельных сайтов судов с разными форматами,
  на каждом — капча на входе в картотеку.
- В картотеках часто нет ИНН сторон — ломает матчинг «дело ↔ контакт».
- Вывод: парсинг несопоставимо сложнее КАД при нулевой ценности для задачи.

### 2.5. СудАкт (sudact.ru) — не подходит

Крупная база судебных актов, включая арбитраж. **API нет**, только сайт —
парсинг вернул бы нас к анти-бот проблемам без выигрыша.

### 2.6. Casebook, Контур.Фокус, Rusprofile API и подобные — избыточно

Модули судебных дел есть, но это enterprise-подписки от тысяч рублей/мес,
без осмысленного бесплатного лимита. Для тестового задания избыточно.

## 3. Итоговое решение

**Собственный парсер КАД (внутренний JSON-API + cookie-fetcher на Playwright).**

Причины:
1. Бесплатно и без ограничений на число запросов (в отличие от 200/мес у parser-api).
2. Полный контроль: поиск по датам + роль «ответчик», все 3 типа дел (гражданские,
   административные, банкротные) — ровно то, что нужно заданию.
3. Проверенная механика: есть несколько живых open-source примеров.
4. Не требует ключей и регистрации (parser-api недоступен без ключа,
   API-Cloud — без юрлица).

Ограничения/риски, которые принимаем: зависимость от актуальных cookies
(Cloudflare), возможность IP-блокировки при агрессивной частоте — контролируем
интервалами опроса и ретраями.

## 4. Последствия для архитектуры

- Модуль источника реализует **только прямой парсинг КАД**:
  cookie-fetcher (Playwright) + запросы к внутреннему JSON-API КАД
  (`POST /Kad/SearchInstances` и аналоги для административных и банкротных дел).
  Сторонние агрегаторы (parser-api.com и др.) в проекте не используются —
  никаких абстракций/реализаций под них не делаем.
- Cookie-fetcher — отдельный компонент (Playwright), cookies кэшируются,
  обновление по 403/по расписанию.
- Дедупликация дел по GUID карточки/номеру (уникальный индекс в БД).
- Опрос: раз в N минут по фильтру «дата регистрации = сегодня»,
  `InnType = Respondent`, CaseType: G + A + B; судебные поручения — не парсим.
