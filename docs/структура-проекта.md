## Ключевые решения

- Парсинг только напрямую из КАД; агрегаторы не используются.
- Доступ к КАД — через живую браузерную сессию (Playwright): сайт защищён
  DDoS-Guard и pravocaptcha (WASM), программные запросы без неё получают 451.
  Подробности — в docs/получение-данных-с-кад.md.
- Дедупликация дел — уникальный индекс по GUID карточки/номеру.
- Матчинг сторон дела с контактами — по имени/ФИО (нормализация: ОПФ, кавычки,
  ё→е, регистр), а не по ИНН: у физлиц-ответчиков ИНН в КАД часто нет.
- Уведомления — журнал `notifications` с уникальной парой (дело × контакт):
  письмо не дублируется, а ошибка SMTP повторяется в следующем цикле опроса.
- Статусы отправок (`pending → sent/failed`) + timestamp + ID письма — фиксация рассылки.
- Ответы клиентов → лид в Bitrix24 (`crm.lead.add`) с привязкой к делу.
