# План разработки проекта

## Исходная цель
Автоматизация информирования потенциальных клиентов о новых судебных делах (КАД kad.arbitr.ru), поиск совпадений по базе контактов и отправка коммерческих предложений.

---

## Текущий статус и дорожная карта

```
[ГОТОВО: Этап 1]  Клиент и парсер КАД (Playwright, Xvfb, пагинация, ретраи, суды, роли участников)
        │
        ▼
[ГОТОВО: Этап 2]  База данных и модели ORM
  ├── SQLAlchemy async + asyncpg + Alembic
  ├── Модели данных: Case / Side, Contact
  └── docker-compose.yml (PostgreSQL + env) и первая миграция
        │
        ▼
[ГОТОВО: Этап 3]  Скрипт наполнения тестовыми контактами
  └── scripts/seed_contacts.py:
        • Заполнение таблицы `contacts` реалистичными тестовыми данными (включая ООО "РЕМИСТР")
        • Опция `--clean` для сброса и перезаполнения
        • Идемпотентный upsert по ИНН
        │
        ▼
[Этап 4: Сервис рассылки (Mailer)]
  └── app/services/mailer.py:
        • Асинхронная отправка email по SMTP (`aiosmtplib` / `email.message`)
        • Формирование тела письма с деталями дела (номер дела, суд, стороны, ссылка на карточку)
        │
        ▼
[Этап 5: Проверка сквозного сценария]
  └── Скрипт проверки цепочки:
        • Получение дела из КАД (или тестового дела)
        • Выборка целевого контакта из БД (по совпадению ИНН/названия)
        • Отправка письма через Mailer
```

---

## Детализация этапов

### Этап 2: База данных и модели ORM
1. **Зависимости и конфигурация**:
   - `pyproject.toml`: добавление `sqlalchemy>=2.0`, `asyncpg`, `alembic`.
   - `app/config.py`: параметры подключения `database_url`.
   - `docker-compose.yml`: сервис PostgreSQL 16 с volume и healthcheck.
2. **Базовый модуль БД (`app/database.py`)**:
   - `create_async_engine`, фабрика сессий `async_sessionmaker`, `Base = DeclarativeBase`.
3. **Модели (`app/models/`)**:
   - `Case` (`id`, `guid`, `case_number`, `case_type`, `court`, `judge`, `start_date`, `created_at`) с уникальным индексом по `guid`.
   - `Side` (`id`, `case_id`, `role`, `name`, `inn`, `address`) со связью `ForeignKey("cases.id")`.
   - `Contact` (`id`, `company_name`, `inn`, `email`, `phone`, `is_active`, `created_at`).
4. **Миграции (Alembic)**:
   - Инициализация асинхронного `env.py`.
   - Первая миграция создания таблиц `cases`, `sides`, `contacts`.
5. **Тесты**:
   - Тесты CRUD и отношений моделей через pytest.

### Этап 3: Скрипт наполнения тестовыми контактами
1. `scripts/seed_contacts.py`:
   - Наполнение таблицы `contacts` тестовыми записями (включая компании из реальных тестовых выборок КАД, например ООО "РЕМИСТР", для сквозного тестирования).
   - Опция `--clean` для сброса и перезаполнения.

### Этап 4: Сервис рассылки (Mailer)
1. `app/services/mailer.py`:
   - Настройки SMTP в `app/config.py` (хост, порт, логин, пароль, отправитель, режим SSL/TLS).
   - Формирование HTML/plain-text сообщений с подстановкой параметров дела.
   - Асинхронная отправка через `aiosmtplib`.

### Этап 5: Сквозной сценарий
1. `scripts/e2e_pipeline.py`:
   - Запуск пайплайна: парсинг дела -> поиск ответчика среди `Contact` по ИНН -> отправка КП через `Mailer`.
